# 浄めばやし ボイス制作記録

公式MCP `kitan-lore` の `get_spirit` と、公式配布wavから弁天の声を制作した記録。
手順の正本は [shikifuda-kasane/docs/VOICE.md](../../shikifuda-kasane/docs/VOICE.md)（6段の手順・つまずき早見）。
本書はそこからの差分——**この作品だけの尺の壁（2.0秒／1.5秒）に、標準の後処理（atempo単体）では届かなかった**点を中心に書く。

## 話者・台詞（2本）

**弁天**（雑賀・水／「川端の弁天堂に唄を奉じる、水辺の唄い手」）。一人称「わっち」・呼び方「ぬしさん」・花魁風の廓詞「〜でありんす」「〜なんし」。

| ファイル | 場面 | 台詞 | 尺の上限 | 実測 |
|---|---|---|---|---|
| `koe_start.m4a` | 開幕（「月夜に入る」押下0.25秒後・帳が開く間） | さあ、ぬしさんに、唄を一つ | 2.0秒以内 | **1.95秒** |
| `koe_dawn.m4a` | 夜明け（色の札を叩いた／取りこぼした0.26秒後・結果札の前） | 唄は、ここまでありんす | 1.5秒以内 | **1.50秒** |

台詞はオーナー・文章担当の確定稿のまま使用（書き換えなし）。

## 声の出どころ

- **Irodori-TTS**（`kitan-works/tools/Irodori-TTS`・uv・MPS）
- 参照音声: 公式配布wav `https://vibe.co.jp/luna-occulta/media/voice/benten_sample.wav`（48kHz mono・10.88秒。ライセンス「AIに読み込ませてOK・単体再配布はNG」）。**リポジトリには置いていない**（生成にだけ使用・スクラッチ領域から削除済み）
- caption（`get_spirit` の `voice_sample.voice_design_caption`）: 「気品のある大人の女性の落ち着いた低い声。凛として滑らかに話している。クリアな音質。」

```bash
export PATH="$HOME/.local/bin:$PATH"
cd kitan-works/tools/Irodori-TTS
uv run --no-sync python infer.py --hf-checkpoint Aratako/Irodori-TTS-v4.1-Small \
  --text "<台詞>" --ref-wav <benten_sample.wav> \
  --caption "気品のある大人の女性の落ち着いた低い声。凛として滑らかに話している。クリアな音質。" \
  --model-device mps --codec-device mps --seed <42|43|44> --output-wav out.wav
```

テイクは各台詞3本（seed 42/43/44）。生の出力は両台詞ともテイク間で尺がほぼ同じ（start全テイク3.52秒・dawn全テイク2.96秒＝**参照音声の話速に強く支配される**、既知の癖どおり）。Whisper文字起こしで内容が最も安定して一致した**seed 43をどちらも採用**（1キャラ＝1音源の原則は参照wav側で満たしており、seedは声質を変えない）。

## つまずき: atempoの上限（1.35倍）だけでは尺に届かない

`shikifuda-kasane/scripts/trim-voice.py` の手順（発声区間検出→atempo上限1.35→フェード→正規化）をそのまま適用したところ:

| | 発声区間 | atempo 1.35倍後 | 上限 |
|---|---|---|---|
| koe_start | 3.42〜3.49秒 | **2.53〜2.59秒** | 2.0秒 |
| koe_dawn | 2.84〜2.92秒 | **2.10〜2.17秒** | 1.5秒 |

どちらも上限に届かない。式札かさね・月影とびの目安（3.4秒）に対し、この作品の上限は台詞の意味で決まった短さ（開幕は帳の開閉に、夜明けは結果札の表示に合わせた尺）で、標準の後処理では埋まらない差だった。

**原因を波形で確認**: 20ms窓RMS包絡で無音区間を見ると、弁天の参照音声は「、」の間が**700〜1080ms**（seed間でばらつきあり）と、通常のコンマ間（100〜300ms程度）の3〜5倍長い。一方、母音・子音そのものの発声区間（無音を除いた実際に鳴っている時間）は start 1.4〜1.6秒・dawn 1.4秒程度しかない。**時間の大半は「間」であって、声そのものは短い。**

## 対処: 「間」だけを狙って詰める（新規の後処理）

atempoで声そのものを一律に早回しすると、上限に届かせるには1.7〜1.95倍が必要になり（試作して確認）、Whisperでの文字起こしが崩れ始めた（例: 「ありんす」→「ありず」、「ぬしさんに」→「ぬしちゃんに」）。**声を変形させず、不自然に長い「間」だけを短くする**方式に切り替えた。

手順:

1. 発声区間検出（10ms窓RMS包絡・ピーク比6%・前後40msの余白）で頭と末尾の無音を落とす
2. **内部の無音区間のうち、しきい値（400ms系）を超える区間だけ**を上限（150〜200ms＝普通のコンマ間相当）まで詰める。しきい値未満の短い間（子音の切れ目・語と語の間の自然な間）は**一切触らない**——ここを一律に詰めると「ありんす」の「んす」が「ず」に潰れるような破綻が起きた（試作で実際に踏んだ）
3. それでも尺上限を超える分だけ、atempo（**上限1.35倍を厳守**）で仕上げる
4. フェードアウト0.12秒 → 音量正規化（ピーク0.88・24kHz mono wav）

実際に使ったパラメータ:

| | 間の圧縮対象 | 圧縮後の上限 | atempo | 結果 |
|---|---|---|---|---|
| koe_start（目標1.95秒） | 400ms超のみ | 200ms | 1.256倍 | 2.42s→**1.95s** |
| koe_dawn（目標1.50秒） | 250ms超のみ | 80ms | 1.280倍 | 1.92s→**1.50s** |

atempoは両方とも1.35倍の上限内に収まっている（声の変形は最小限）。加工スクリプトは検証用に一時領域で作った使い捨てのため、このリポジトリには置いていない（`scripts/` の既存ファイルには触れない指示のため）。同じ壁に次回もぶつかったら、この記録の手順を再現すればよい。

## 開幕の作り直し（2026-09-03）

`koe_start.m4a` が不採用となり、テイク違い＋別台詞で候補を作り直した。**`assets/audio/koe_start.m4a` はまだ差し替えていない**（採用が決まってから実装側で差し替える）。候補一式は `kitan-circle/data/voice-kiyome-start/`（試聴ページ `index.html` に12候補＋旧版比較用1本を base64 埋め込み）。

### 分かったこと

- **同じ台詞でも、参照wavの話速（「、」の間が長い）は seed を変えても引き継がれる。** 新規6テイク（seed 50〜55）の生の尺は全テイク3.52秒で一致。間の長さ（700〜850ms級が2箇所）もほぼ同じ位置に出る。**「別のテイクを引けば自然に短くなる」は成立しない**——短くしたいなら台詞そのものを設計し直す必要がある。
- **読点を抜いても、この参照音声はどこかに大きな間を作る。** 「唄いんす」（4モーラ・読点なし）ですら生の尺は2.12秒あり、内部に約1000〜1100msの間が1つ入った。duration predictor がテキストに対してある程度の長さを見込み、余った分を間として埋めている可能性がある。**間圧縮という技法自体は、この参照音声を使う限り避けられない**——ただし「間を作る余地が最初から小さい短い台詞」を選べば、圧縮量そのものを減らせる。
- 上の理由で、**「唄いんす」1本だけは頭尾のトリムのみ（間の圧縮なし）で2.0秒上限をわずか0.12秒しか超えなかった**（他の全候補は0.76〜1.47秒超過）。短い台詞を選ぶことで「圧縮するかどうか」を选べる状態まで持ち込めた。
- **前回と同じ「400ms超の間を200msへ＋atempo」処理を新しい seed（52）へ適用したら、前回と同じ「頭のAACロス」が再現した**（wav では「さあ、虫さんに、歌を一つ」→ AAC変換後「さ、虫さんに、歌を一つ」）。take を変えても現象が再現したことで、**原因が take ではなく処理（圧縮＋atempoで頭を薄くする）側にある疑いが強まった**。
- 同じ素材（seed52 の生成物）を「最小圧縮＋atempo1.285倍」で処理したときと「旧レシピ＋atempo1.185倍」で処理したときとで、Whisperの「ぬしさん」判定が割れた（前者は正しく拾い、後者は「虫さん」と誤る）。**音量・尺はほぼ同じでも処理の違いでASR結果が変わる**——この揺れ自体が「境界的な発音」のサインなので、この take を採るなら人の耳での確認を厳重にする。

### つまずき: 「〜んす」語尾がテイクごとに違う崩れ方をする（koe_s4・koe_s5第1案）

koe_s4「還ってきなんした」とkoe_s5「さしんす」は、最初の3テイク（seed42/43/44）とも文字起こしの語尾が崩れた。

- koe_s4: 「気軽した」「帰ってきました」「悲難した」——3テイクとも**別々の**崩れ方
- koe_s5: 「刺身す」「写真す」「刺身す」——「ん」の脱落／近い音への寄り

いずれもseedごとに崩れ方が違う。同じ「〜んす」系でも、s2・s3・koe_s5対案は3テイクとも**同じ**寄り方の表記揺れ
（読みは合っているが漢字の選び方が揺れる、教訓どおりの癖）で、こちらとは性質が違う。
**同じ崩れ方がテイクを変えても続く＝ASR側の癖／テイクごとに違う崩れ方をする＝発声そのものが不安定、を見分けてから、
後者だけ追加テイクを引く**という判断をこの日行った。追加でseed45/46（koe_s4）・47/48（koe_s5）を生成したところ、
koe_s4はseed45で「月が帰ってきなんした」と完全一致、koe_s5はseed48で「なみまに、あけのいろがさしんす。」と完全一致した。

## 判断が要る点（曲の節目）

1. koe_s5は台詞2案（第1案「波間に、明けの色がさしんす」／対案「渚にも、唄が沁みてゆきんす」）を両方生成した。
   **第1案を推す**——文字起こしが「なみまに、あけのいろがさしんす。」と完全一致した一方、対案は3テイクとも
   「渚」「沁みて」の音が「長さ」「締めて」寄りに聞こえ、読みの安定度で第1案が上回る。対案はボイス帖に参考として
   残した（`assets/audio`には未配置）。**最終判定はオーナーの耳で**（イヤホン推奨）。
2. koe_s2「花びらが、舞い込みんす」は全テイクでWhisperが「マイコミンス」とカタカナ書きするが、読み
   （マイコミンス＝まいこみんす）自体は一致している。表記の崩れであり読みの崩壊ではないと判断した。
3. 実出力の目標値（-13.2dB）は`koe_dawn`（SE_VOL 1.0時点の素の値）に揃える形で決めた。ゲームには全効果音共通の
   `sfxBus`（0.9倍）が別途かかるため、体感音量は表の値よりさらに約0.9dB下がる（`koe_dawn`は2026-09-03時点の記録で
   -14.1dB相当）。この基準を変えたい場合は`koe_dawn`側の基準を先に見直す必要がある。

### 音量の訂正（2026-09-04・実装担当が検算）

`koe_start` の `SE_VOL` を **0.36 → 0.62** に直した。0.36 は素の -9.0dB から **-17.9dB** まで沈める値で、
基準（`koe_dawn` の -13.2dB）より4.7dB低かった（差4.2dBを埋める倍率は `10^(-4.2/20)=0.62`）。
**dBの差から倍率を出すときは必ず 20·log10 で検算する**（前回は実装担当＝私の当て推量だった）。
節目5本（0.66／0.82／0.69／0.88／0.92）は測り直しても -13.1〜-13.3dB で揃っている。
