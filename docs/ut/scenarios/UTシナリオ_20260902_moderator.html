0. 目的・範囲・前提

  • 対象ユーザー: リンクを踏んで初めて来た人。『月蝕綺譚』は知っているが、本作固有のルール（闇の札だけを叩く・百八枚で満願・曲が替わる・稽古・番付）は知らない。
  • 対象ジャーニー: 開く → 何のゲームか分かる → 帳をくぐる → 最初の1枚をとめる → 浄化と誤操作の違いを知る → 速さの上がりと曲の切り替わりに気づく → 満願に届く → 結果を読む → 図鑑を見る → もう一度／再訪 → 音を切る → 稽古を探す → 順位を探す → 別の配布経路。
  • 対象外: 速度曲線・段の割り当ての妥当性そのもの（値の裁定は企画の持ち場）、二次創作ガイドライン適合、実機での体感速度・音の折り返し（docs/DEVELOPMENT.md に「オーナーの耳・実機待ち」と明記済みの2件）、わいわいの枠（iframe）内の本物の番付描画。
  • 実施環境: このリポジトリを観察スクリプトが http://127.0.0.1:8972/ 相当のローカルポートで配信したもの（実行時は空きポートを自動選択）。本番 origin（github.io・わいわいタウン）では実施しない——枠の外では localStorage に記録が落ちるため、本番の kiyome-bayashi_save（オーナーの最高枚数・図鑑）を書き換えてしまう。waiwai.town 宛のリクエストは全件遮断し、束の保存・番付の送信・番付の取得は自作 stub（window.waiwai）に差し替える。
  • 受入の正本: docs/SPEC.md（節番号で追跡。§2 盤面・§3 速度・§4 曲が替わる夜／開幕・§5 音・§6 稽古・§7 番付）、README.md、docs/DEVELOPMENT.md 末尾（2026-09-02 の節・「満願の見せ場」が未着手と明記）。
  • 前回との比較: 本作は初回のUT（目付）。scripts/playtest.js（機械検査9件）は既に緑だが、あれは「終わりまで行くか・送信0か」を見る検査で、初見の人の理解・迷い・表示の食い違いは別の観点として本UTで見る。
実施順の逸脱について（明示）: 設定の execution.order は非破壊→可逆変更→不可逆の順だが、 本作は案内カード（A-1）を経ないと盤面に入れない単一の遊び体験であり、体験順に実施する。 可逆変更は localStorage の1キー（kiyome-bayashi_save の束、UT用 origin に限る）に限られ、 不可逆・外部影響の操作は、枠の外で開く限り存在しない（submitScore は自作 stub が受け、実際の waiwai.town へは1件も送らない。#autotest／#autocut は記録も番付も触らない設計＝canSubmitScore()）。
