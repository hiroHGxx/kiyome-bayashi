# 浄めばやし — 仕様書

『月蝕綺譚 -Luna Occulta-』二次創作・第7弾。**このファイルが仕様の正本。**実装が変わったら追従させる。

企画の裁定と型えらびの経緯は `kitan-circle/data/articles/20260901-1510-7sakume-plan.json`。

## 1. ゲーム概要

| | |
|---|---|
| 型 | **落下タイル（Piano Tiles / 别踩白块儿型）** |
| 一行で | **叩くほど、闇に沈んだ御霊が一柱ずつ色を取り戻す。手が止まった夜に、夜が明ける。** |
| 遊び方（1行） | 四筋を落ちてくる**闇の札だけ**を、下から順にタップして浄める |
| プラットフォーム | モバイル縦持ち1画面・**論理 480×720 の固定**（端末に合わせて同率で縮むだけ・伸ばさない。理由は §2「盤の高さを伸ばさない」） |
| 尺 | **百八枚で満願**（実測 **96秒**）。その先は延長で枚数を伸ばす |
| 世界観 | 蝕に呑まれて色を失った御霊を、囃子の拍に合わせて一柱ずつ浄めていく一夜 |

### 圧はどこから来るか

**速度。**浄めるたびに落下が速くなる。止まったら終わる型なので、圧が遊びに内蔵されている（外付けの設計が要らない）。

### 中毒性の3層

| 層 | 中身 |
|---|---|
| micro | 叩いた瞬間に**墨色→極彩色**に戻って弾ける＋**琴が次の音を鳴らす**（叩き続けると旋律になる） |
| core | 浄めた枚数。速度が上がり続けるので、枚数がそのまま腕前 |
| meta | **図鑑29柱**。浄めた柱が灯る。全29柱で「満天」 |

## 2. 盤面・入力

### 盤面 — 一対（2026-09-01 実寸で4案を見比べて確定）

- **縦四筋。**筋幅 **120**（論理480÷4）。行高 **180**（札絵が 1024×1536＝2:3 なので、120×180 に**切り取りも余白もなく**収まる）。
- **1行に札は2枚だけ。**
  - **闇の札 1枚**（段03）＝叩く。
  - **色の札 1枚**（段10）＝叩いてはならない。
  - 残る **2筋は空**（宵闇の地のまま）。
- **「闇に沈んだ一柱」と「すでに顕れた一柱」が毎行いっしょに落ちてくる。**対比が作品の主題そのものになり、
  なおかつ **2筋が空いているので目が休まり、どちらの絵も読める。**
- 行は上から下へ**連続で流れ落ちる**（段送りではない）。
- **闇の札には金の枠を入れる（金泥 `#D9A94C`・6px・内側に宵闇 `#131320` の2px を添える）。**
  地が暗い柱（`nekomata` `dan` `shinra` `kohaku`）は、枠が無いと**札ではなく穴に見える**（実測）。
  - **2026-09-02 改訂。**当初は「2px・`rgba(212,175,55,.55)`」と書いていたが、**実機寸法（390×844・DPR2）の
    実写真で見えなかった**（盤の全体写真で3枚中2枚しか判別できず、2倍に拡大して初めて3枚とも出ていると分かった）。
    **コードは正しく描いていた。正しく描かれているのに見えていない。**枠の役目を果たしていないので太らせた。
  - あわせて `rgba(212,175,55,.55)`（＝`#D4AF37`）は **`data/design-tokens.json` に無い値**だった（仕様を書いた側の誤り）。
    金泥 `#D9A94C`（用途「枠・数値」）へ直した。**色は系から選ぶ。新しい値を発明しない。**
  - 内側の暗い線は、**絵の明るい柱でも金の縁が溶けない**ようにするため（特定の柱に手当てをせず、印そのものを直す）。

### 盤の高さを伸ばさない（2026-09-02 裁定）

骨の `fitCanvas` は 480×720 を**同率で縮めるだけ**で、高さを伸ばさない。§1に「高さは伸びる」と書いていたが、
**伸ばさない方を正とする。**理由は**番付の公平さ**——高さが端末で変わると、**背の高い端末ほど先の行が見えて易しくなる。**
全国の番付で枚数を競う作なので、**盤は誰の端末でも同じでなければならない。**
（余白は題字とHUD・断り書きが使うので、実機で見て損はしていない。実測: 390×844 で canvas 390×585）
- **HUD を札の上に重ねない。**盤の上に不透明の帯を確保する（半透明だと明るい札に負ける・実測）。

### 落とした並べ方（実寸で見比べた・蒸し返さない）

| 案 | 中身 | 落とす理由 |
|---|---|---|
| 敷き詰め | 闇03×1＋色10×3（全4筋を埋める） | **16枚すべてが主役級の決め絵で、画面が騒がしい。**「絵が大きく出る」を狙って、逆に**一枚も見てもらえない**画になった |
| 原典 | 闇03×1＋空×3（Piano Tiles そのまま） | 静かで美しいが**画面がほぼ空**。札絵290枚を使う理由が消え、関門④を自分で落とす |
| 淡彩 | 闇03×1＋色05×2 | 段05（月夜の淡彩）は美しいが**段03とトーンが近すぎる。**速度の中で「叩いてよい札」との見分けが危うい。段05は満願の演出に回す |

### 入力 — 1タップ＝1枚を浄める

- **見るのは「画面のどの筋を叩いたか」だけ。**指の高さは判定に使わない。
- **最下段の未浄の行**の闇の筋と一致すれば **浄化**。一致しなければ **夜明け（終わり）**。
  空の筋を叩いた場合も「一致しない」＝夜明け（**判定は一致か否かの一本だけ。例外を作らない**）。
- 未浄の行が**下端から出はじめたら** **夜明け（取りこぼし）**（実装は行の上端が `H - 行高 = 540` を越えた時。
  「札が完全に消えるまで待つ」にすると、見えない札を叩かされる1行ぶんの空白ができる）。
- **間違った操作は「色の札の筋を叩く」1つだけ。**説明が要らないのはここ（関門⑥）。
- 浄めた行はそのまま流れて下端から出ていく（消さない）。

### 守ること（骨に焼き込み済み／PLAYBOOK）

- 開始・再開直後 **700ms は入力を受けない**。
- 案内カードは `ready` が付くまで `pointer-events:none`。
- iOS のダブルタップズーム抑止（350ms）・`gesturestart` は等倍のときだけ。
- 下段の要素は **bottom 基準**で置く（御霊そろえの帯の教訓）＋ `env(safe-area-inset-bottom)`。

## 3. 進行と終わり

### 速度

| 記号 | 値 | 意味 |
|---|---|---|
| `H` | 180 | 行高（論理px） |
| `V0` | **145 px/秒** | 初速（≒1.24秒/行） |
| `ACC` | **×1.006 / 1枚** | 浄めるたびに乗じる |
| `VMAX` | **520 px/秒** | 上限（≒0.35秒/行）。**満願までには届かない。効くのは延長だけ**（下記） |
| 助走 | 最初の3行は **V0×0.7** | 触れば分かるための猶予（別モードにしない） |

108枚で `1.006^108 ≈ 1.91` 倍＝**277px/秒**（0.65秒/行）。

**実測（2026-09-01・自動プレイ・`scripts/playtest.js` ①）**

| 測ったもの | 値 |
|---|---|
| **満願（108枚）まで** | **96.1秒**（2回とも同値。受け入れ基準の 60〜120秒 に入る） |
| 満願時の速度 | 277 px/秒 |
| `VMAX` に噛みつく枚数 | **214枚**（148.7秒） — **満願の先＝延長でしか効かない** |
| 延長260枚まで | 164.7秒・自動プレイは通る・例外0 |

想定していた「約80秒」は外れ、**96秒**だった。`V0`／`ACC` は動かさない（基準に入っているため）。

### 終わり方

- **百八枚を浄めきると「明けの祓い」＝満願。**見せ場（§4）を出したあと、**延長（蝕の刻）**へ続く。枚数は青天井。
- 夜明けの条件は2つだけ: **色の札の筋を叩いた／未浄の行を取りこぼした。**

### 絵の選び方（遊びの規則ではない・説明もしない）

- **その夜にまだ浄めていない柱が、闇の札として出る。**一度浄めた柱は、以後**色の札の側に回る**。
- 29柱を一巡したら全部が闇に戻る（＝月が欠ける）。**遊ぶ側は気づかなくてよい。**絵の辻褄が合うだけ。
- 闇の筋は乱数。ただし**同じ筋が3行続けて闇になることは無い**（片手の親指だけで押し切れる並びを避ける）。
- 色の札の筋も乱数。**闇の筋と隣り合う行が続かないようにする**（対比が一番効くのは離れているとき）。

### 段03・段10 の実物（2026-09-01・29柱すべてを240px幅で目視）

- **段03は「モノクロ」ではない。**ほぼ墨色だが、**色が一点だけ乗る**柱がある
  （`anne` の赤い襟巻き／`atoza` の赤帯／`aun` の赤角／`izuna` の青髪／`karma` の赤マント／
  `nemu` の虹髪／`sakuya` の赤紐／`uka` の赤袴／`shinra` の赤目）。**仕様に「モノクロ」と書かない。**
- **それでも識別は崩れない。理由は色ではなく構図。**
  - **段03＝夜空の下を横向きに歩く全身像。**余白が多く、地は宵闇。
  - **段10＝正面の決め絵。**極彩色・金の紋・蝕環が**札の全面**を埋める。
  - **並べた瞬間に「絵の量」が違う。**速度の中でも間違えようがない（実寸の盤で確認済み）。
- **240px幅（＝筋幅120論理px × DPR2）で29柱すべて誰か読める。**四筋の設計は通る。

## 5. 音（MEDIA.md）

- **浄めるたびに琴が次の音を鳴らす。**音階は **都節音階**（宵闇の側。ヨナ抜き長音階は明るすぎる）。
  上行して一巡したら次の高さへ。**叩き続けると旋律になるのが、この型の中毒の芯。**
- 合成は **Karplus-Strong 弦**（御霊おとしの琴を流用。宵あらわし §19.2 と同じ手）。**200Hz未満の純音はスマホで鳴らない。**
- 夜明けの音・満願の音。公式ミニゲーム音源のSE9種（`end` / `whiff` ほか）は**完全未使用の在庫**なので当たる。
- BGM は入れない（拍そのものが遊びなので、別の拍とぶつかる）。**この判断は題名『浄めばやし』の根拠でもある。**

### 折り返しの決めどころ（オーナーの耳で決める・2026-09-02）

いまの実装は **220Hz から12音上がり、932Hz に届いたら上の5音だけを繰り返す**
（御霊おとし・宵あらわしの折り返しをそのまま流用）。実測は
220 / 233.1 / 293.7 / 329.6 / 349.2 / 440 / 466.2 / 587.3 / 659.3 / 698.5 / 880 / 932.3 Hz、以後 587.3〜932.3 の5音。

**懸念**: 一夜は108枚＝約96秒ある。**別々の音は最初の12枚だけで、残り96枚は高い側の5音の反復**になる。
「叩き続けると旋律になる」を芯に置いた題名なので、ここが薄いと題名の根拠が弱る。

**対案**: 12音を上りきったら **220Hz へ戻ってまた上る**（鋸歯状）。一夜で上りの句が9回くり返される形になり、
囃子の反復に近づく。低い側が戻るので高音の疲れも避けられる。

**どちらが良いかは鳴らして聴くまで決まらない**（会社ノート「声は設定だけで選べない」）。
**紙の上で決めず、オーナーの耳で裁定する。**

### 実装・実測（2026-09-02・音響担当）

- `purify(r)` のたびに `kotoStep` を1つ進め、`noteFreq(kotoStep)` を鳴らす。`resetRun()` で
  夜ごとに0へリセット。`scaleFreq` は都節音階 `[0,1,5,7,8]` を5段ごとに1オクターブ上げる作りなので
  「上行して一巡したら次の高さへ」がそのまま成り立つ。932Hz（step>11）を上限に1オクターブ折り返す
  （弦モデルは高音ほど N=sr/freq が細り楽器らしさが崩れる。御霊おとし・宵あらわしと同じ上限）。
  220Hz起点＝常にモバイルの床200Hzを超える
- **実測**: OfflineAudioContextで20ノート分を実レンダリングし自己相関で基音を確認。全ステップが
  期待値と±30セント以内で一致。220→233→294→330→349→440→466→587→659→699→880→932Hz と実際に
  階段状に上がり、折り返し後も587→932Hzの反復上昇を確認。実プレイ（実クリック）でも `kotoStep` が
  タップと同数だけ進み、エラー0
- BGM・声・夜明けの音・満願の音・SE9本（`assets/audio/`）はこの便では未着手（次便へ）

### 夜明け・満願の音／音量の釣り合い（2026-09-02 第2便・音響担当）

- **夜明け（色の札を叩いた／取りこぼした）＝ `whiff`、満願（108枚）＝ `end`。** 公式SE9本のうち
  この2本だけ使い、残り7本（`bomb`/`combo`/`count`/`fukaku`/`kiwami`/`start`/`zan`）は未使用のまま
  `assets/audio/` から削除した（ガイドライン＝使わない素材は置かない）。選定は帯域を実測して決めた:
  `end`・`whiff` はどちらも400Hz未満に音圧の大半が集まる低音寄りの音（`highpass=2000` で-48〜-55dB
  まで落ちる）＝ Karplus-Strong の琴と質感が割れない。`whiff` は既存作でも一貫して「外した／誤タップ」
  の役なので、色の札を叩く／取りこぼす＝夜明けの意味にも素直
- **音量は「琴が主役・夜明けと満願がその次」の指定どおりに実測で並べた**（0.1秒窓RMSの最大値＝鳴った
  瞬間。Chromeでのデコード後、sfxBus 0.9 込み）:

  | 音 | 出力（鳴った瞬間） | 頻度 |
  |---|---|---|
  | 琴（一夜の平均・開始12音） | -18.1dB | 毎回 |
  | 琴（108枚のほとんどを占める反復5音） | -19.1dB | ほぼ毎回 |
  | 満願（`end`・SE_VOL=0.4） | -20.2dB | 108枚で1回 |
  | 夜明け（`whiff`・SE_VOL=0.7） | -21.5dB | 1回／1プレイ（終わりに必ず1回） |

  どちらも琴の平均より2.6〜3.6dB下＝主役を食わない。ゲイン値は実測しながら決めた
  （最初の目安 whiff=0.5 は-24.4dBまで沈み、夜明けとしては弱すぎたので0.7へ上げ直した）
- **実装は `assets/audio/` の実ファイルを持ちつつ、Artifact版は base64を直接埋め込む**（`fetch("data:")`
  は既存作（宵あらわし・御霊そろえ）の教訓どおりArtifactのCSPで通らないため）。`index.html`（Pages）は
  `fetch("assets/audio/<name>.m4a")` の実ファイル取得、`dist/artifact.html` は `build-dist.js` が
  `src/game.js` の `SE_NAMES` を読み取って `window.AUDIO_DATA` にbase64を注ぎ、`atob()` 経由で
  `decodeAudioData` する。両経路とも実機で確認済み（後述）
- **検証**: ①`index.html` を実サーバーで開き `fetch` 経路でデコードが通ること ②`window.AUDIO_DATA` を
  注入し `assets/audio/*` へのリクエストを遮断した状態（Artifactを模した状態）でもデコードが通ること
  ③ `dist/artifact.html` を実際に開き、同様にネットワークを遮断してもデコードが通ること——の3つとも
  エラー0で通した。さらに**実クリックで音あり本番プレイを再現**し、108枚めの瞬間に `end` が1回、
  わざと外した瞬間に `whiff` が1回、狙った箇所からだけ鳴ることを呼び出し回数で確認（二重発火・
  早すぎる発火は無し）
- **`playSe()` は `soundOn` を先頭で見て早期returnする**（琴の `pluckOut()` と同じ形）ので、♪の
  切り替え釦で夜明け・満願も含めて全部止まる。稽古・自動プレイは `soundOn=false` で始まる
  （`begin(false)`）ため、この2音も既存の琴と同様に鳴らない＝送信0の検証に影響しない
- `playtest.js`（8件）・`kitan-precheck`（生成物だけに書かれたコードが無い、含む）とも通した
- **未着手**: BGM・声（この作はもともと入れない仕様）。折り返しの決めどころ（§5冒頭）はオーナーの耳
  待ちのまま、今回も手を付けていない

## 7-a. 全国ランキング・番付
